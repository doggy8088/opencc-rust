# 兩字詞語意風險分析與保守白名單設計

本次把「少改壞原意」放在「把所有疑似中國用語都改掉」之前。實作採高風險詞預設保留、已審核片語才轉換，並同步 Rust、JavaScript、Python、Swift、C# 的 tw2 與 twp。

## 為何全域替換不可靠

這些不是全部都能當作地區同義詞：

| 詞 | 應轉的明確語境 | 應保留的不同語意 | 主要風險 |
| --- | --- | --- | --- |
| 質量 | 視頻質量→影片品質 | 物體質量、高質量恆星 | 改變物理量 |
| 文本 | 純文本→純文字、文本框→文字方塊 | 文學文本、法律文本、文本分析 | 把作品／文件整體降成文字材料 |
| 窗口 | 瀏覽器窗口→瀏覽器視窗 | 辦事窗口、機會窗口、窗口大小 | 改壞實體與比喻 |
| 站點 | Web站點→Web網站 | 公車站點、物流站點 | 把交通與觀測地點改成網站 |
| 小白 | 電腦小白→電腦新手 | 小白老師、小白花、小白狗 | 誤改姓名或複合詞的一部分 |
| 登錄 | 帳號登錄→帳號登入 | 實價登錄、戶籍登錄、資料登錄 | 把記錄／登記誤解成驗證登入 |
| 訪問 | 訪問API→存取API、訪問網站→造訪網站 | 訪問學者、出國訪問、訪問總統 | 混淆資訊資源與人物訪問 |
| 私信／私聊 | 私信功能→私訊功能 | 歷史人物的私信、飯後私聊幾句 | 混淆信件、口頭談話與即時訊息 |
| 粘貼／黏貼 | 複製粘貼→複製貼上 | 把海報粘貼在牆上、封箱黏貼 | 混淆實體膠黏與剪貼簿操作 |
| 打印 | 遠程打印→遠端列印 | 心中打印著回憶、單用打印 | 把未知的實體／比喻用法硬套成電腦列印 |
| 踩坑 | 開發踩坑→開發踩雷 | 山路踩坑、工地踩坑 | 把實際踩坑改成另一個比喻 |
| 項目 | 軟體項目→軟體專案 | 測試項目、管理項目、維護項目 | 把清單事項當成 project |

這不是只憑推測增加例外。教育部辭典明確把「質量」當成物理量；教育部自己的文章使用「文本分析」；內政部的系統使用「實價登錄」與「諮詢窗口」。由這些實際用例可推論，相關裸詞不能一律視為待修正的地區用語。[教育百科：質量](https://pedia.cloud.edu.tw/Entry/Detail/?title=%E8%B3%AA%E9%87%8F)、[教育部台語語料庫介紹](https://www.moe.gov.tw/News_Content.aspx?n=9E7AC85F1954DDA8&s=2BF92E180FD68C1A)、[內政部實價查詢操作指引](https://olvr.land.moi.gov.tw/jsp/guide.jsp)。

「產品質量」也不夠明確：「產品質量為十公斤」仍可能指 mass。因此本次不把它列為通用轉換，只接受「產品質量不好／優良」等已明確表達品質的片語。片語長度不是唯一的安全條件，語意證據才是。

## 方案比較

以下是工程取捨分析；只有前後版本的正反例結果在下一節做了實測，沒有對其餘方案宣稱準確率。

| 方法 | 優點 | 風險／成本 | 決定 |
| --- | --- | --- | --- |
| 全域替換＋持續補例外 | 覆蓋快、規則少 | 未知用法直接被改；例外永遠追不上 | 撤回高風險詞的全域替換 |
| 高風險詞全部保留 | 避免這些詞的誤轉 | 原始網站與技術文件中的正例會漏轉 | 作為未知語境的預設 |
| 整篇出現科技關鍵字就套用 | 可提高技術文章覆蓋 | 技術文章也會討論物理、人物、行政；遠處關鍵字會污染判斷 | 不採用 |
| 明確片語白名單＋較長保護詞 | 可審核、可重現、跨語言一致 | 需要逐步累積語料；仍無法理解任意句法 | 本次採用 |
| 詞性／斷詞／語意模型 | 有機會處理遠距語境 | 本次未評估準確率；增加模型、部署、效能與五種語言的一致性成本 | 暫不加入正式轉換流程 |

最可靠的可落地方式是：對無法判定的內容維持原詞，持續加入人工確認過的正反例。模型或語料掃描可以協助找候選詞，不應直接把候選詞批量寫成正式全域規則。

## 本次落實的防線

1. `guarded` 收錄 17 個高風險詞頭：質量、文本、窗口、站點、小白、登錄、訪問、踩坑、粘貼、黏貼、私信、私聊、打印、項目、保存、通過、套餐。裸詞都保留。
2. 各詞頭附原因與明確白名單，目前 160 筆；另有保存、通過、套餐與專案等既有片語規則。沒有用「所有名詞 × 所有動詞」大量拼接來製造表面覆蓋率。
3. 對較長的已知反例做保護，例如「文本框架」不能因前綴「文本框」變成「文字方塊架」；「電腦小白鼠」不能因「電腦小白」變成「電腦新手鼠」；「訪問網站負責人」也不轉成造訪網站。
4. 審核上游字典，避免其舊長詞條蓋過保守預設。現在覆寫 tw2 的「高質量→高品質」「項目的→專案的」「項目管理→專案管理」；明確的軟體片語「項目文件夾」「項目設置」則另外審核保留轉換。完整清單由 `disabled-upstream.json` 產生。
5. 產生器拒絕把 guarded 裸詞放回全域對應、拒絕冒充白名單的裸詞、拒絕衝突目標、拒絕未審核的單字元擴寫。「賬→帳」「羣→群」是僅有的單字元字形修正。
6. 五種語言共用同一份規則與驗收語料。Rust 逐筆驗證全部產生詞條經簡轉繁後的結果與冪等性，各語言都執行相同的語意正反例。

相鄰詞性規則也有收緊：

- 通過：移除「這個／此／該／上述」等不能代表手段的短觸發詞；較長的「通過系統驗證」「通過網路認證」保留達成義。
- 保存：移除「保存到／至／為」「立即保存」「確認保存」等弱證據，避免改壞「保存到博物館」「保存至今」「確認保存證據」。保留點擊保存、自動保存、保存設定等已審核動作。
- 套餐：會員、付費、價格、月費也可能用於餐飲，不再僅憑這些詞就轉方案。訂閱、雲電腦、API 等明確片語仍轉方案。
- 項目：移除建立、管理、維護、測試等不足以證明 project 的泛用組合。

這次會有意減少轉換量。例如單用「登錄」「文本」「窗口」「私信」會保留；正向語境的來源變體，如「帳號登入／账号登录／帳號登錄」，仍統一成「帳號登入」。同一文件同時有「實價登錄」與「帳號登入」是語意正確的差異，不是詞彙不一致。

## 實測前後對照

`semantic-cases.json` 有 180 個人工構造的對比案例，包含 121 個應保留例與 59 個應轉例。測試前先記錄上一版本機實作的輸出到 `semantic-before.json`，附規則與 Python 產生字典的 SHA-256；比對程式檢查來源列表，防止案例增刪後仍錯用舊輸出。

| 測試集合 | tw2 上一版 | tw2 新版 | twp 上一版 | twp 新版 |
| --- | ---: | ---: | ---: | ---: |
| 應保留例通過 | 16 / 121 | 121 / 121 | 15 / 121 | 121 / 121 |
| 應轉例通過 | 54 / 59 | 59 / 59 | 54 / 59 | 59 / 59 |

上一版已經有小白菜、質量守恆、服務窗口等例外，仍在這組保留例大量失敗，說明只增加黑名單的侷限。新版的正例也沒有因改成保守預設而在此集合退步。

這個測試集刻意挑選上一版風險，不是隨機抽樣的正式語料，也不是獨立保留的盲測集。不能把上述結果宣稱為「中文轉換準確率 100%」，也不能推論已覆蓋原先 152 頁文件的全部用法。表中指語意目標詞保留，其他既有正字或術語轉換仍可能發生，例如「質量分布→質量分佈」。

原始第 1～7 題驗收句、28 組 tw2 迴歸詞、專名與冪等性仍通過。先前要求裸詞也一律改寫的額外測試，依這次的保守語意要求改為保留，並補上完整技術片語的正例。反向字典沒有變更。

## 殘留風險與後續白名單准入條件

Trie 仍是字串最長匹配，不是完整的中文斷詞或句法模型。較長詞與未知人名仍可能包住白名單片語；同一短語也可能在特殊文章中有不同解讀。像「私信我」在平台對話中很明確，但在談歷史書信的句子裡仍可能出現不同斷句。現有白名單不保證零誤判，例外保護也只能覆蓋已知情況。

新增詞條應符合以下條件：

- 審核完整片語，不只確認那個兩字詞「經常」是某個意思。
- 至少加入一個正例，以及物理／行政／交通／文學／姓名／實體動作等相關領域的反例。
- 測試片語前後再接中文字、已有長詞與專名，檢查是否吞掉詞界。
- 未明確判斷時保留。先收集漏轉例，不用相鄰的「這個、的、前、後、到」等字充當語意證據。
- 檢查上游長詞條是否繞過新預設，並讓五種語言、生成檢查、冪等與效能檢查全部通過。
- 若有真實文件語料，再額外評估誤改率與漏轉率，分領域統計，與人工校閱結果比較；不要只看詞彙取代次數增加多少。
